## 1. 测试策略

### 1.1 总体策略

本测试计划遵循 **测试金字塔** 原则，采用多层次测试策略，确保系统在功能、性能、安全等各个维度达到质量要求。

### 1.2 单元测试（Unit Testing）

| 指标 | 目标值 |
|------|--------|
| 代码覆盖率 | ≥ 80% |
| 核心业务逻辑覆盖率 | ≥ 95% |
| 新增代码覆盖率 | ≥ 90% |
| 测试通过率 | 100% |

**覆盖范围**：
- 服务层（Service）业务逻辑
- 数据访问层（Repository）SQL生成
- 工具类（Util）边界条件
- 业务规则计算（积分、等级、充值等）

**工具**：JUnit 5 + Mockito + JaCoCo

### 1.3 集成测试（Integration Testing）

**策略**：采用 **灰盒测试** 方式，验证模块间交互正确性。

| 测试类型 | 触发条件 | 失败处理 |
|----------|----------|----------|
| API接口集成 | 每次代码提交 | 阻塞合并 |
| 数据库交互 | 每次代码提交 | 阻塞合并 |
| 第三方服务（支付、短信） | 每次代码提交 | 记录并告警 |
| 缓存（Redis）一致性 | 每日定时 | 邮件告警 |

**环境**：准生产环境（Staging），数据脱敏处理

### 1.4 端到端测试（E2E Testing）

| 场景 | 工具 | 执行频率 |
|------|------|----------|
| 核心业务流程 | Playwright | 每日回归 |
| 用户注册/登录 | Playwright | 每日回归 |
| 预约全流程 | Playwright | 每日回归 |
| 支付全流程 | Playwright | 每周完整回归 |

**覆盖率目标**：P0功能 100%覆盖，P1功能 ≥90%覆盖

## 4. 安全测试

### 4.1 SQL注入防护

| 用例ID | 测试场景 | 预期结果 |
|--------|----------|----------|
| SEC-SQL-001 | `' OR '1'='1` | 查询无效，返回空结果 |

| SEC-SQL-003 | `UNION SELECT password FROM admin` | 联合查询被拦截 |
| SEC-SQL-004 | `1 AND SLEEP(5)` | 布尔盲注被拦截，响应<1秒 |
| SEC-SQL-005 | 数字型参数传入字符串 | 类型校验失败，提示参数错误 |

**防护措施验证**：
- [ ] MyBatis使用 `#{}` 而非 `${}`
- [ ] ORM框架SQL注入过滤
- [ ] 数据库最小权限原则
- [ ] SQL审计日志开启

### 4.2 XSS跨站脚本攻击

| 用例ID | 测试场景 | 预期结果 |

| SEC-XSS-004 | 富文本输入（允许部分HTML） | 仅允许安全标签（p、br、em） |

**防护措施验证**：
- [ ] 输入参数过滤（白名单）

### 5.4 缺陷等级定义

| 等级 | 定义 | 修复要求 |
|------|------|----------|
| 严重（S0） | 数据丢失、系统崩溃、安全漏洞 | 必须立即修复，24小时内 |
| 高危（S1） | 核心功能不可用、数据错误 | 2天内修复 |
| 中危（S2） | 功能部分受损、用户体验差 | 1周内修复 |
| 低危（S3） | UI问题、文案错误、边缘case | 2周内修复 |
| 建议（S4） | 优化建议 | 评估后决定 |
